# 联机本场战绩

联机牌桌右上角点击「战绩」，在墨玉金色面板中按局查看本场所有已结束的对局。最新局排在前面，可以分页选局，也可以用「上一局 / 下一局」浏览。结算弹窗收起后仍可打开，整场结束后返回大厅之前也能查看。

- 每局显示胡牌玩家的历史头像、昵称、胡牌方式和整局净输赢。
- 清一色、七对、龙七对、碰碰胡等大胡与杠上开花、抢杠胡等特殊牌型使用金色标签。硬胡、软胡和杠倍数不当作特殊牌型。
- 四家记录均包含真实头像昵称、本局净输赢和结束积分。赢家高亮，正数绿色、负数红色、零为中性色。
- 荒庄显示「本局无胡牌」，仍保留四家此前已产生的分数变化。
- 面板适配 844×390、667×320 横屏与安全区，长昵称省略显示，支持多局分页。打开面板期间触摸和滑动不会穿透到手牌。

输赢使用每局开始到结束的分数差，包含中途的杠分、跟庄分等变化，而非仅胡牌时的支付额。头像昵称在本局公开结算时冻结，不随后续资料变化而改写。服务器快照中的 `roundHistory` 是唯一数据来源，重复快照不会追加重复记录，换局和断线重连仍保留历史。新场或显式重置清空。

这些记录属于当前活动房间的这场游戏，不是跨场账户战绩。房间回收后不在此入口展示。后端仍沿用现有的持久化战绩逻辑。

## 部署

本次功能包含后端改动：先在后端仓库的 `main` 更新代码并重启房间服务，再从前端 `master` 运行 `pnpm build:mini`，重新编译或发布小游戏。已运行中的旧房间无法补记更新前的完整历史，应从新场验收。

旧服务端没有 `roundHistory` 字段时，面板显示「服务器暂未支持战绩」，不会伪造历史。已有完整记录时，前端没有收到某局 `hand_result` 也可通过重连快照恢复。

## 验证

```sh
pnpm test
pnpm test:mini
pnpm typecheck
pnpm typecheck:mini
pnpm build:mini
node miniprogram/scripts/round-history-smoke.mjs
cd backend
.venv/bin/python -m pytest tests/test_round_history.py -q
```

Windows 后端 Python 路径为 `.venv/Scripts/python.exe`。专用后端测试覆盖真实 WebSocket 断线补齐、公开结算边界、历史身份冻结、荒庄、中途记分、去重，以及真实 4/8/16 局驱动直至终局的净额一致性。浏览器宿主运行四份小游戏构建包，替换微信网络和登录 API，检查四家座位旋转、历史头像、两种横屏尺寸、16 局分页、终局、新场和重连。截图与报告输出到 `docs/evidence/miniprogram-round-history/`。

微信真实头像授权、图片域名和真机表现仍需用已配置 AppID 的体验版检查。
